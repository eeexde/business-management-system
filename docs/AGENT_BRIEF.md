# Builder brief (shared by all module agents)

Project: **BizDesk**, a business management app (portfolio quality). Repo root: `C:\Users\user\work\business-management-system`. Read `docs/PLAN.md` first.

## Ground rules

- **Next.js 16.3** with App Router. APIs differ from older versions. Before using an API you're unsure of, check `node_modules/next/dist/docs/01-app/`. Key points:
  - `params` and `searchParams` are **Promises**: `const { id } = await params`.
  - Use the global helper types `PageProps<"/customers/[id]">` and `LayoutProps<...>` (generated by `npx next typegen`).
  - Middleware is now `src/proxy.ts` (already done; don't touch it).
- **Zod v4**: `z.email()`, `{ error: "msg" }` for messages, and `z.coerce.number()` for form numbers.
- All authenticated pages live under `src/app/(app)/<module>/`. The layout (sidebar plus auth) already exists.
- **Money is integer cents.** Use `parseMoney`, `formatMoney`, and `centsToInput` from `@/lib/utils`. Dates are `YYYY-MM-DD` strings. Use `today()`, `addDays()`, and `formatDate()` from `@/lib/utils`.
- **Currency**: get it from `getSettings()` (`@/lib/queries/settings`) and pass it to `formatMoney(cents, settings.currency)`.
- **Server Actions** go in `src/app/(app)/<module>/actions.ts` with `"use server"`. Pattern:
  ```ts
  export async function createX(_prev: ActionState, formData: FormData): Promise<ActionState> {
    const auth = await authorize("customers:write"); // from @/lib/auth
    if (!auth.ok) return auth.state;
    const parsed = Schema.safeParse(Object.fromEntries(formData));
    if (!parsed.success) return fieldErrors(parsed.error); // from @/lib/action-state
    // ... db write (use db.transaction for multi-table writes)
    await logActivity({ userId: auth.user.id, action: "x.created", entityType: "x", entityId, summary: "Created …" });
    revalidatePath("/x");
    redirect(`/x/${id}`); // or return { ok: true, message: "Saved." }
  }
  ```
  For non-form actions (delete, status change) take plain args, check permission with `authorize`, and return `ActionState` or redirect.
- **Reads** go in `src/lib/queries/<module>.ts` (with `import "server-only"`). Pages are async Server Components that call these. Call `requireUser()` from `@/lib/auth` in pages when you need the user or role.
- **Permissions**: use `can(user.role, "x:write")` from `@/lib/permissions` to hide buttons in the UI. Always enforce on the server with `authorize()`.
- **UI kit** (use it, don't reinvent): `@/components/ui/*`: `Button`, `LinkButton`, `SubmitButton`, `Input`, `Textarea`, `Select`, `Field`, `Card`, `CardHeader`, `CardBody`, `Badge`, `Table`/`THead`/`TBody`/`TR`/`TH`/`TD`, `PageHeader`, `EmptyState`, `StatCard`, `FormMessage`, `ConfirmButton` (two-click delete; never use `window.confirm` or `alert`), `SearchInput`, `FilterSelect`. Icons come from `lucide-react`. Theme tokens are `bg-card`, `bg-muted`, `text-muted-foreground`, `border`, `text-primary`, `bg-primary`, `text-success`, `text-warning`, `text-danger`. Dark mode works automatically through these tokens; never hardcode gray or white colors.
- Forms are Client Components using `useActionState(action, initialActionState)` and show field errors through `<Field errors={state.errors?.name}>`.
- Every list page needs: a `PageHeader` with a primary action, search and filters where sensible, a `Table` inside a `Card`, an `EmptyState` when empty, and pagination when there can be more than 25 rows (use `?page=` with simple prev/next links).
- Add `export const metadata = { title: "…" }` on pages.
- Pure business logic goes in `src/lib/<module>.ts` with Vitest tests in `src/lib/<module>.test.ts`.
- Code quality: strict TypeScript, no `any`, accessible labels, responsive (works at 375px wide), and consistent with the existing files. Match existing comment density.
